# 添加新文章或页面

本文面向参与维护 SCEX 文档站的协作者，说明从创建 Markdown 文件到发布页面的完整流程。

## 1. 创建页面文件

在项目根目录中新建一个以 `.md` 结尾的文件，例如：

```text
server-guide.md
```

文件名建议遵循以下规则：

- 使用小写英文、数字和连字符。
- 不使用空格、中文文件名或特殊符号。
- 文件名应简短并能表达页面内容，例如 `install-guide.md`。
- `README.md` 是站点首页，不应作为普通文章覆盖。
- `_sidebar.md` 和 `_coverpage.md` 是 docsify 配置页面，不应作为普通文章使用。

页面会由 docsify 直接读取，不需要额外生成 HTML。以 `server-guide.md` 为例，其访问地址为：

```text
/#/server-guide
```

## 2. 编写页面内容

每篇文章应以清晰的一级标题开始：

```markdown
# 服务器使用指南

这里是页面简介，用一至两句话说明本文用途。

## 准备工作

正文内容。

## 操作步骤

1. 第一步。
2. 第二步。
3. 第三步。
```

编写时请注意：

- 一级标题只使用一次。
- 主要章节使用二级标题，尽量少使用四级及以下标题。
- 中文与半角英文、数字之间添加半角空格。
- 中文句子使用全角标点和直角引号「」。
- 段落之间保留一个空行。
- 命令、文件名和代码使用反引号包裹，例如 `index.html`。
- 图片使用相对路径，避免绑定本地计算机上的绝对路径。

完整的排版和配色约定请参阅[站点样式规范](skill-webstyle.md)。

## 3. 添加到侧栏

创建文件后，编辑根目录的 `_sidebar.md`，在合适的分组下添加链接：

```markdown
- 使用指南

  - [服务器使用指南](server-guide.md)
```

侧栏中的文字是读者看到的页面名称，括号内是实际文件路径。两者可以不同，但链接路径必须与文件名完全一致。

如果页面没有添加到侧栏，仍可通过地址直接访问，但读者难以发现，因此普通文章都应登记在侧栏中。

## 4. 添加站内链接

从一篇文章链接到另一篇文章时，直接使用 Markdown 文件路径：

```markdown
[查看服务器使用指南](server-guide.md)
```

链接到当前页面的某个章节时，使用标题生成的锚点：

```markdown
[跳到操作步骤](#操作步骤)
```

不要在普通文章中写死域名或 `/#/` 路由。使用相对的 Markdown 路径可以让本地预览和部署后的站点同时正常工作。

## 5. 使用站点元件

文档站提供了几种可复用的提示元件。

提示信息：

```html
<div class="tips">这里填写补充信息或操作建议。</div>
```

正确或已完成的操作：

```html
<div class="approved">这里填写正确做法或完成状态。</div>
```

需要注意的事项：

```html
<div class="caution">这里填写可能造成问题的注意事项。</div>
```

错误或危险操作：

```html
<div class="warning">这里填写禁止操作或严重警告。</div>
```

普通引用或简短说明优先使用 Markdown 引用块：

```markdown
> 这里是一段补充说明。
```

不要在文章内添加独立的配色、字体或布局样式。需要新的通用元件时，应统一修改 `styles.css`，并先确认它符合站点样式规范。

## 6. 本地预览

不要直接双击打开 `index.html`。docsify 需要通过 HTTP 服务加载 Markdown 文件。

如果已安装 Python，可在项目根目录执行：

```powershell
python -m http.server 3000
```

然后在浏览器中访问：

```text
http://localhost:3000
```

预览结束后，在终端中按 `Ctrl+C` 停止服务。

## 7. 提交前检查

提交修改前，请逐项确认：

- [ ] 新页面使用了明确且稳定的文件名。
- [ ] 页面包含一个一级标题，并有简短的用途说明。
- [ ] `_sidebar.md` 中已经添加入口。
- [ ] 侧栏链接、站内链接和图片路径均可访问。
- [ ] 标题层级连续，没有从二级标题直接跳到四级标题。
- [ ] 代码块标注了语言，例如 `markdown`、`css` 或 `powershell`。
- [ ] 页面在桌面端和窄屏下均可正常阅读。
- [ ] 未修改或删除 `.nojekyll`。
- [ ] 未把临时文件、个人路径或敏感信息加入仓库。

<div class="approved">完成以上检查后，新页面即可随站点部署一同发布。</div>

## 8. 示例目录结构

添加 `server-guide.md` 后，项目结构可能如下：

```text
.
├── .nojekyll
├── _coverpage.md
├── _sidebar.md
├── adding-pages.md
├── index.html
├── README.md
├── server-guide.md
└── styles.css
```

其中 `index.html` 负责加载 docsify，`README.md` 是文档首页，`_sidebar.md` 定义侧栏，普通 `.md` 文件对应各个文章页面。
